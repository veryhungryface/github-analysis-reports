이 레포는 무엇을 도와주나?

문제

AI 에이전트는 간단한 요구에도 새 의존성, 래퍼, 추상화, 보일러플레이트를 만들기 쉽습니다.

해결

Ponytail은 에이전트에게 YAGNI → 표준 라이브러리 → 플랫폼 기능 → 기존 의존성 → 한 줄 → 최소 구현 순서로 멈춰 생각하게 합니다.

결정 사다리: 먼저 덜 만든다

1

생략

정말 필요한 기능인지 먼저 확인

2

Stdlib

언어 표준 기능이 있으면 사용

3

Native

브라우저·OS·DB 기본 기능 우선

4

재사용

이미 설치된 의존성만 활용

5

한 줄

가능하면 짧고 명확하게

6

최소 구현

그다음에만 필요한 만큼 작성

누구에게 유용한가

AI 코딩 사용자

에이전트가 불필요한 코드를 늘리는 문제를 줄이고 싶을 때

리뷰어

현재 diff에서 무엇을 삭제할 수 있는지 빠르게 보고 싶을 때

팀 리드

새 의존성·추상화·미래 대비 코드를 줄이는 팀 규칙이 필요할 때

에이전트 도구 제작자

여러 에이전트/에디터에 같은 행동 규칙을 배포하고 싶을 때

벤치마크 관심자

코드량·비용·응답시간 감소 실험을 재현하고 싶을 때

핵심 기능

항상 켜지는 규칙

AGENTS.md와 각 호스트 어댑터가 에이전트에게 최소 구현 원칙을 주입합니다.

명령형 스킬

/ponytail, /ponytail-review, /ponytail-audit, /ponytail-debt로 모드 전환·과설계 리뷰·부채 추적을 제공합니다.

넓은 이식성

Claude Code, Codex, OpenCode, pi, Gemini CLI, Cursor, Windsurf, Cline, Copilot, Kiro 등 다양한 호스트용 어댑터를 포함합니다.

벤치마크가 말하는 것

효과 신호

README 기준 5개 일상 과제, 3개 모델, 10회 반복 중간값에서 baseline 대비 코드 80–94% 감소, 비용 47–77% 감소, 응답 3–6배 단축을 주장합니다.

해석 주의

작은 로컬 모델에는 의사결정 사다리 전이가 약하다고 문서화되어 있습니다. 실제 팀 코드베이스와 사용하는 모델에서 재현 확인이 필요합니다.

채택 전 확인할 점

시도 추천

AI 에이전트가 “요구보다 크게” 만드는 문제가 반복되는 팀, 특히 리뷰 비용과 코드 소유 비용을 줄이고 싶은 팀에게 적합합니다.

먼저 검증

자주 맡기는 실제 작업 3~5개로 코드량, 정확성, 리뷰 수고, 보안/접근성 누락 여부를 비교하세요. 단순함이 품질 저하로 이어지면 모드를 낮춰야 합니다.

실행 판단

Ponytail은 “코드를 더 잘 쓰게 하는 프레임워크”보다 “코드를 덜 쓰게 만드는 에이전트 성격/규칙 배포판”에 가깝습니다.

빠른 검증 방법: 사용하는 에이전트에 설치한 뒤, 평소 과하게 구현되던 작은 작업 하나를 맡기고 결과 diff가 실제로 짧아졌는지 확인하세요.
