HKUDS/CLI-Anything

소프트웨어를
에이전트용 도구로 바꾸는 허브

GUI 앱, SaaS, 개발 도구를 AI 에이전트가 찾고 설치하고 실행할 수 있는 CLI 하네스와 스킬 문서로 묶는 저장소입니다.

누구에게 좋나Blender, GIMP, LibreOffice, OBS 같은 기존 도구를 에이전트 작업 흐름에 붙이고 싶은 팀
한 줄 판단개별 앱 자동화 코드 모음이 아니라, “도구 발견 → 설치 → 실행 → 미리보기”까지 다루는 agent-native CLI 생태계입니다.
먼저 볼 것원하는 앱 하네스가 실제 운영체제·상위 앱 설치·인증 조건을 만족하는지 먼저 확인해야 합니다.
1도구 탐색

cli-hub list와 검색으로 여러 소프트웨어용 CLI 하네스를 한 번에 찾습니다.

2설치 지원

registry의 install command와 entry point를 기준으로 필요한 하네스를 설치하게 돕습니다.

3구조화 결과

에이전트가 파싱하기 쉬운 JSON 출력, REPL, one-shot 명령 패턴을 목표로 합니다.

4미리보기 루프

일부 하네스는 생성 결과를 preview bundle/session으로 남겨 사람이 확인할 수 있게 합니다.

5작업 지도

video-creation 같은 matrix가 여러 CLI와 공개 도구를 묶어 복합 작업 경로를 제안합니다.

6스킬 문서

각 하네스는 SKILL.md로 설치·제약·명령 흐름을 에이전트가 읽을 수 있게 정리합니다.

입력에서 결과까지

핵심 흐름은 에이전트가 “무슨 도구를 써야 하지”에서 멈추지 않게 만드는 것입니다.

실제로 돌려본 것

보고서 작성 중 로컬에서 최소 확인 경로를 실행했습니다.

통과

registry.json, matrix_registry.json, public_registry.json이 JSON으로 검증됐고, cli-hub 0.4.1 editable install 후 list/search가 실행됐습니다.

주의

cli-hub list --json은 101개 항목을 반환했지만, 개별 하네스는 실제 앱·서버·인증이 있어야 완전히 쓸 수 있습니다.

도입 전에 확인할 것

필요 앱 설치

GIMP, Blender, LibreOffice처럼 원본 앱이 필요한 CLI는 런타임 준비가 먼저입니다.

권한과 보안

로컬 파일, API 토큰, GUI 자동화 권한을 쓰는 하네스는 샌드박스와 백업 전략이 필요합니다.

작업 단위 선택

matrix 전체를 무작정 설치하기보다 필요한 capability만 좁혀 설치하는 방식이 안전합니다.

결론

CLI-Anything은 “한 앱을 자동화하는 라이브러리”보다 여러 앱을 에이전트가 다룰 수 있게 표준 통로를 만드는 허브에 가깝습니다. 기존 소프트웨어를 AI 작업자에게 맡기려는 팀이라면, 먼저 한두 개 하네스로 작은 산출물을 만들어 보는 게 좋습니다.
