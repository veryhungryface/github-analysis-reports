생성 실험을
로컬에서 굴리는 스튜디오

이미지·비디오 생성, 편집, 브랜칭, 히스토리 저장을 한 화면과 CLI에서 다루는 로컬 우선 visual generation runtime입니다.

누구에게 좋나AI 이미지·영상 결과를 반복 비교하고, 프롬프트·참조·모델 경로를 잃지 않고 관리하려는 제작자와 에이전트 워크플로 팀
한 줄 판단단순 생성기보다 “여러 제공자 + 로컬 기록 + 노드식 탐색”을 묶은 작업대에 가깝습니다.
먼저 볼 것Node 22 이상, 인증 방식, 기본 모델 설정, 실제 과금/크레딧 경로를 자기 환경에서 먼저 확인해야 합니다.
1이미지·비디오 생성

텍스트, 참조 이미지, 편집, 영상 생성까지 한 런타임에서 다루며 결과를 로컬 히스토리에 남깁니다.

2여러 제공자 라우팅

GPT OAuth/API, Grok, Gemini, Antigravity, MCP 연동을 lane 단위로 고르고 기본값도 fail-closed로 관리합니다.

3노드·멀티모드 탐색

좋은 결과를 가지치기하거나 같은 프롬프트를 여러 슬롯으로 비교해 실험 루프를 빠르게 돌립니다.

4캔버스 정리

줌, 주석, 지우개, 배경 정리, 투명 프리뷰로 결과물을 다음 생성의 재료로 다듬을 수 있습니다.

5로컬 갤러리

생성 결과와 메타데이터를 세션 단위로 저장하고, 다시 선택·복사·연장하는 흐름을 지원합니다.

6에이전트용 CLI·스킬

ima2 CLI와 bundled skill 문서가 있어 코딩 에이전트가 생성 파이프라인을 재사용하기 쉽습니다.

입력에서 결과까지

핵심 흐름은 프롬프트를 한 번 던지고 끝내는 게 아니라, 모델 선택과 결과 재사용을 계속 추적하는 구조입니다.

입력프롬프트, 참조 이미지, 영상 조건
모델 선택lane/defaults로 제공자 경로 고정
생성·편집Classic, Node, Multimode, Canvas
저장·재사용로컬 갤러리, 세션, CLI 출력

레포 성숙도 신호

짧은 기간에 활발히 릴리즈되는 프로젝트라 기능 폭은 넓지만, 실제 팀 도입 전에는 인증·모델·비용 정책을 따로 검증해야 합니다.

실제로 돌려본 것

분석 중 저장소를 직접 체크아웃하고 최소 실행 경로를 확인했습니다.

통과

npm ci --ignore-scripts, npm run typecheck, npm run build:cli, node bin/ima2.js --help까지 성공했습니다.

주의

소스 체크아웃 직후에는 bin/ima2.js가 없어 CLI가 바로 실행되지 않습니다. 먼저 npm run build:cli가 필요했습니다.

도입 전에 확인할 것

인증 경로

OAuth, API key, Grok/Gemini 경로가 실제 계정과 운영 정책에 맞는지 확인해야 합니다.

로컬 데이터

갤러리와 히스토리를 로컬에 남기는 장점이 있지만, 팀 공유·백업 방식은 별도 설계가 필요합니다.

업데이트 속도

릴리즈가 빠른 만큼 모델명, 비용, provider 제한이 바뀔 수 있어 고정 버전 테스트가 필요합니다.

결론

ima2-gen은 “이미지 하나 뽑는 도구”가 아니라 생성 실험을 기록하고 분기하고 다시 쓰는 작업대입니다. AI 이미지·영상 제작을 자주 하는 팀이나, 코딩 에이전트에게 시각 생성 루틴을 맡기려는 팀은 작은 샘플로 먼저 돌려볼 가치가 큽니다.
