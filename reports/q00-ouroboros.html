무엇을 도와주나?

Ouroboros는 “AI에게 바로 만들어 달라”는 방식의 실패를 줄이고, 먼저 요구사항의 숨은 가정과 성공 기준을 드러낸 뒤 실행 가능한 Seed 명세로 고정합니다. 이후 여러 AI 코딩 런타임이 같은 계약을 따라 작업하고, 결과를 평가하며 다음 루프로 개선합니다.

1

아이디어

막연한 목표·문제 입력

2

인터뷰

소크라테스식 질문으로 모호성 제거

3

Seed

불변 명세와 수용 기준 생성

4

실행

Codex·Claude 등 런타임으로 작업

5

평가

기계·의미·합의 검증

6

진화

평가 결과를 다음 명세에 반영

해결하는 문제

AI가 추측으로 구현하는 문제

요구사항이 흐리면 AI는 빈칸을 임의로 채우고, 사용자는 뒤늦게 재작업을 반복합니다.

검증 없는 “좋아 보임” 문제

Ouroboros는 명세, 이벤트 기록, 평가 게이트를 통해 무엇을 왜 만들었는지 추적 가능한 작업 단위로 바꿉니다.

로컬 실행인가?

도구 자체는 로컬 우선

Python 패키지/CLI/MCP 서버로 설치되어 로컬 프로젝트와 이벤트 저장소를 기준으로 움직입니다.

LLM은 선택한 런타임에 따름

Codex, Claude, Gemini, Copilot 같은 외부 CLI/API 계정이 필요할 수 있습니다. 로컬 LLM만으로 완결되는 도구라고 보긴 어렵습니다.

고성능 GPU 필수는 아님

주 역할은 모델 추론 자체보다 명세·오케스트레이션·검증입니다. 무거운 계산은 연결한 AI 런타임/모델 쪽 성능과 요금에 좌우됩니다.

도입 전 확인할 점

시도 추천

AI 코딩 작업을 “프롬프트 한 번”이 아니라 인터뷰 → 명세 → 실행 → 평가 루프로 관리하고 싶은 개발팀/파워유저에게 적합합니다.

먼저 검증

Python 3.12+ 환경, 사용 중인 AI CLI 인증, MCP 등록, 팀의 기존 이슈/PR 프로세스와 맞는지 작은 기능 하나로 테스트하는 것이 좋습니다.
