무엇을 도와주나

3D 도시 장면을 손으로 클릭해서 만드는 대신, Python 스크립트와 규칙으로 쌓아 올린 뒤 같은 자산을 브라우저와 영상으로 재사용하게 해줘.

코드 기반 3D 제작

건물, 도로, 사람, 차량, 카메라 이동을 스크립트로 재현할 수 있어.

시각 검증 문화

렌더가 성공 코드만으로는 충분하지 않다는 점을 체크와 문서로 고정해둠.

브라우저 전환

.blend 결과를 GLB·모션·샷 데이터로 내보내 three.js에서 보여줌.

프레임 단위 영상

화면 녹화가 아니라 브라우저가 프레임을 직접 그려 영상을 생성함.

흐름은 단순해

입력은 도시 규칙과 스크립트, 처리는 Blender, 출력은 .blend와 WebGL·영상 산출물로 이어져.

1

규칙 작성

도시 배치, 색, 카메라, 검증 기준을 코드에 둠.

2

장면 생성

Headless Blender가 레이어별로 city.blend를 갱신함.

3

웹 내보내기

GLB, motion, shot, sky 데이터를 브라우저로 넘김.

4

검증·녹화

렌더 밝기, 충돌, 교통, 프레임 캡처를 확인함.

도입 판단

라이브러리처럼 가져다 쓰기보다, “코드로 만든 3D 씬을 끝까지 제품 화면과 영상으로 보내는 법”을 배울 때 가치가 커.

바로 볼 만함

생성형 3D 파이프라인, WebGL 포트폴리오, Blender 자동화 샘플이 필요한 팀.

먼저 확인

Blender 5.2, Node 18+, ffmpeg, 폰트 경로 등 로컬 환경 준비가 필요함.

주의점

브랜드 로고와 상업 폰트는 코드 라이선스와 별개로 직접 사용 권리를 판단해야 함.

기술 신호

작지만 문서 밀도와 검증 철학이 강한 저장소야. Python이 중심이고 웹 파트는 three.js/Vite로 구성돼.

구성

blib 라이브러리, scripts/city 단계, docs/city 문서, web 브라우저 빌드로 나뉨.

검증

겹침, 부유, 교통, 표지판, 크라우드 등 시각 실패를 숫자로 확인하는 스크립트가 있음.

웹 비용

README 기준 GLB 약 3.3MB, 427 draw calls, M4 Pro에서 60fps 목표.

라이선스

코드는 0BSD지만 로고·폰트·벤더 스킬은 별도 권리 확인이 필요함.

짧은 결론

이 저장소는 “멋진 도시 데모”보다 “3D 장면을 코드로 만들고, 검증하고, 브라우저와 영상까지 연결하는 작업 방식”이 더 핵심이야. 직접 쓰려면 먼저 ./bl scripts/verify_setup.py와 web 실행까지 자기 장비에서 통과하는지 보는 게 좋아.
