게임보다 루프가 더 재밌어

겉으로는 카트 게임 데모지만, 핵심은 에이전트가 만든 결과물을 화면과 플레이 하네스로 계속 비판하고 고치는 측정 루프야.

아트 없이 화면 구성

트랙, 카트, 텍스처, 이펙트, 오디오를 로드 시점에 코드로 생성함.

명확한 아트 바

ART_DIRECTION.md가 조명, 팔레트, 재질, 리뷰 점수 기준을 고정함.

플레이 감각 측정

드리프트가 실제로 빠른지, 카메라가 멀미나는지, 터치가 먹는지 하네스로 봄.

브라우저 실전 이슈

검은 프레임, GL 컨텍스트 손실, 모바일 메모리, 셰이더 히치까지 다룸.

흐름은 이렇게 봐

코드 규칙이 게임 자산을 만들고, 실제 브라우저 화면과 플레이 기록이 다시 개선 지시로 돌아와.

1

규칙

트랙, 물리, 재질, 오디오, UI 기준을 코드와 문서에 둠.

2

생성

메시·텍스처·사운드를 런타임에 절차적으로 만듦.

3

실행

Vite 기반 브라우저 게임으로 플레이하고 녹화함.

4

측정

샷·FPS·드리프트·터치·모바일 하네스로 회귀를 잡음.

도입 판단

완성 게임 엔진이라기보다 웹게임 제작, 절차 생성, 에이전트 개발 루프를 배울 샘플로 보는 게 맞아.

바로 볼 만함

Three.js/WebGL 게임, 절차 생성 아트, AI 에이전트 오케스트레이션 사례가 필요한 사람.

먼저 확인

npm install, npm run build, 실제 브라우저 플레이가 자기 환경에서 되는지 봐야 함.

주의점

스크린샷 비평은 플레이 버그를 못 잡는다고 README가 직접 말함. 사람 플레이와 하네스가 같이 필요함.

기술 신호

코드는 TypeScript 중심이고, src/는 렌더·월드·카트·게임·FX·UI·오디오로 쪼개져 있어.

규모

README는 약 60,500라인/49개 소스 파일을 언급하고, pygount 기준 코드 라인은 약 38k로 잡힘.

의존성

핵심 런타임은 three, postprocessing, n8ao, simplex-noise 조합.

점수 감각

README 기준 전체 시각 점수는 62/100, 드리프트 감각은 74/100으로 솔직히 공개함.

라이선스

GitHub 메타데이터는 MIT로 잡히지만 package.json에는 ISC가 남아 있어 재사용 전 LICENSE 파일 기준 확인이 좋아.

짧은 결론

이 저장소는 “브라우저 카트 게임”을 보는 것도 좋지만, 더 중요한 건 에이전트가 만든 결과를 실제 픽셀과 플레이 하네스로 계속 검증하는 방식이야. 웹게임이나 절차 생성 프로젝트를 만들 때 측정 루프 예제로 꽤 쓸 만해.
